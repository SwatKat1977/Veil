# Contributing to Veil

First of all — thank you for your interest in contributing to Veil.

Veil is an open-source remote tabletop gaming platform focused on collaborative storytelling, immersive roleplay experiences, and accessible online play. Whether you're fixing bugs, improving documentation, designing UI, suggesting features, or contributing code, your help is genuinely appreciated.

We want Veil to be a welcoming and creative community where contributors of all experience levels feel comfortable participating.

Please take a moment to read these guidelines before contributing.

---

# Ways to Contribute

There are many ways to help improve Veil, including:

- Reporting bugs
- Suggesting features or improvements
- Improving documentation
- Fixing typos or inconsistencies
- Writing tests
- Improving UI/UX
- Contributing code
- Reviewing pull requests
- Helping with accessibility improvements
- Discussing gameplay and tabletop tooling ideas

Not every contribution needs to be a large code change.

---

# Before You Start

Please:

1. Read the `README.md`
2. Review the `CODE_OF_CONDUCT.md`
3. Search existing issues before opening a new one
4. Be respectful and constructive in discussions

---

# Development Philosophy

Veil aims to prioritise:

- Accessibility
- Stability
- Maintainability
- Clean architecture
- Collaborative creativity
- Respectful community interaction

When contributing, try to keep solutions:

- Readable
- Modular
- Well documented
- Consistent with the existing codebase
- Focused on long-term maintainability

---

# Reporting Bugs

When reporting bugs, please include:

- A clear description of the issue
- Steps to reproduce the problem
- Expected behaviour
- Actual behaviour
- Screenshots or logs if applicable
- Platform information (OS, browser, etc.)

A good bug report helps us resolve issues faster.

---

# Suggesting Features

Feature suggestions are welcome.

Please try to explain:

- The problem the feature solves
- Why the feature would benefit users
- Possible implementation ideas (optional)
- Potential drawbacks or edge cases

For larger changes, consider opening a discussion before beginning implementation work.

---

# Pull Requests

## Before Opening a Pull Request

Please ensure that:

- Your code builds successfully
- Existing tests still pass
- New functionality includes appropriate tests where possible
- Code style matches the existing project style
- Documentation is updated if necessary

## Pull Request Guidelines

- Keep pull requests focused and reasonably scoped
- Avoid mixing unrelated changes
- Write clear commit messages
- Be open to feedback and revision requests

Maintainers may request changes before merging.

---

# Coding Standards

General expectations:

- Prefer clarity over cleverness
- Write self-documenting code where possible
- Avoid unnecessary complexity
- Follow existing naming and architectural conventions
- Add comments when behaviour is non-obvious

If formatting or linting tools are introduced, please run them before submitting changes.

---

# Documentation Contributions

Documentation improvements are always valuable.

This includes:

- README improvements
- Tutorials
- API documentation
- Setup instructions
- Developer onboarding guides
- Screenshots and examples

Good documentation lowers the barrier for new contributors.

---

# Community Expectations

Please interact respectfully with other contributors.

Healthy disagreement is fine. Personal attacks, hostility, harassment, or toxic behaviour are not.

By participating in the project, you agree to follow the project's `CODE_OF_CONDUCT.md`.

---

# Contributor Licensing

By submitting contributions to Veil, you agree that your contributions may be included in the project under the repository’s open-source licence.

---

# Questions

If you are unsure about anything:

- Open a discussion
- Ask in an issue
- Reach out to the maintainers

Questions are always welcome.

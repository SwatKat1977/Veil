# Security Policy

## Supported Versions

The following versions of Veil currently receive security updates and support.

| Version | Supported |
| ------- | --------- |
| Latest Development Version | Yes |
| Older Versions | No |

As Veil is currently under active development, security fixes will generally be applied to the latest supported version only.

---

# Reporting a Vulnerability

The security of Veil and its community matters deeply to us.

If you discover a security vulnerability, please report it responsibly and privately.

## Please Do Not

- Open a public GitHub issue for security vulnerabilities
- Publicly disclose exploits or vulnerabilities before they are resolved
- Share proof-of-concept exploits that could harm users or infrastructure

## Please Include

When reporting a vulnerability, include as much information as possible:

- A description of the issue
- Steps to reproduce the vulnerability
- Potential impact
- Affected components or versions
- Proof-of-concept code or screenshots if applicable
- Suggested mitigations (optional)

Clear and detailed reports help us respond more quickly and effectively.

---

# Response Process

When a valid security report is received, maintainers will aim to:

1. Acknowledge the report promptly
2. Investigate and validate the issue
3. Determine severity and impact
4. Develop and test a fix
5. Release a security update where appropriate
6. Credit the reporter where desired and appropriate

Response times may vary depending on project availability and issue complexity.

---

# Scope

This policy applies to:

- The Veil application
- Authentication systems
- Networking and communication systems
- Remote multiplayer functionality
- API endpoints
- Data handling and storage
- Build and deployment systems
- Official project infrastructure

Third-party dependencies may have their own separate security policies and disclosure procedures.

---

# Responsible Disclosure

We ask all researchers and contributors to act in good faith and avoid:

- Accessing data belonging to other users
- Disrupting public services or infrastructure
- Performing destructive testing
- Attempting social engineering attacks
- Violating privacy expectations

We support responsible security research intended to improve the safety and stability of the project.

---

# Security Priorities

Veil places strong importance on:

- User privacy
- Secure authentication
- Safe multiplayer interactions
- Protection of user-generated content
- Dependency security
- Stability and reliability
- Safe handling of community-created assets and extensions

---

# Dependency Security

Contributors are encouraged to:

- Keep dependencies updated
- Avoid introducing vulnerable or abandoned packages
- Follow secure coding practices
- Review third-party libraries carefully

Security-conscious development helps protect the entire community.

---

# Disclosure Policy

Once a security issue has been resolved:

- A fix may be released publicly
- Release notes may include security-related information
- Credit may be given to reporters unless anonymity is requested

In some cases, disclosure may be delayed if immediate publication could place users at risk.

---

# Questions

If you have security-related questions or concerns, please contact the project maintainers through the repository’s official communication channels.

Thank you for helping keep Veil and its community safe.
